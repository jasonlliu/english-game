# 移动端界面

紧凑布局适用于宽度不超过 760px，或宽度不超过 1000px 且高度不超过 500px 的横屏。断点在 HUD、场景提示和弹窗中保持一致。

- `mobileHud.css` 统一管理屏幕边缘和安全区。主画面只保留地图、打卡、菜单，以及当前可用的移动和飞行控制。任务、伙伴、帮助和演示工具进入按需加载的 `AdventureMenu`。
- 菜单使用现有 `Panel` / `ModalShell`，因此打开时暂停场景。动作仍交给应用 controller；导航动作先关闭菜单，再调用既有命令。
- `WorldContextActions` 统一安排附近互动。进行中的竞速优先，其后为附近线索、可捕获伙伴、神庙和其他原野活动。手机不同时展示多个详情面板，也不展示被动感知提示。
- `--mobile-context-top` 为顶部事件区位置，`--mobile-bottom/left/right` 为底部控制安全区。新增 HUD 应复用这些区域，避免再添加独立的固定偏移。
- `ModalShell` 在紧凑布局中把关闭工具栏和滚动内容分开。新增弹窗放在内容区内，不再自行绝对定位到弹窗外。
- 神庙提示默认收起；展开后限制高度，摇杆和返回入口保持可见。

回归检查：320×568、375×667、390×667 和 844×390；检查菜单和长地图滚动后的关闭按钮、声音设置、摇杆/奔跑/跳跃、起飞/降落/升降、竞速提示、神庙提示展开；最后恢复桌面视口。实际手机仍应补测触摸、多指操作和浏览器地址栏收缩。

资源约束继续沿用 `npm run check:bundles`，菜单和声音设置不会并入初始 JavaScript。
