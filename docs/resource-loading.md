# 资源与性能

当前模型和场景是程序化 Three.js 几何，没有外部贴图、GLB 或音频包。音乐和音效由按需加载的 Web Audio 引擎合成。现阶段主要成本是 JavaScript、几何创建和 WebGL 资源。先把真实存在的加载边界和生命周期建立好，再按新增素材的实际需要扩展。

## 现有加载策略

- HTML 静态入口只包含 React、存档/规则、HUD 与轻量加载器。Three.js 和世界控制器经动态边界加载。
- `worldLayout.ts` 提供小地图所需坐标与边界，`flightEligibility.ts` 提供伙伴飞行资格；HUD 不静态导入 `world.ts` / `flight.ts` 的树木生成、寻路和飞行模拟。原野寻秘模型跟随 meadow 分包，长篇手记跟随弹窗加载。
- `worldSurvey.ts` 的轻量存档规则随入口加载；世界地图、地区 SVG 图表及交互视图随地图弹窗加载，只复用地标/边界数据，不导入六区 3D 景观。`fieldActivities.ts` 仅保留持久纪录规则，竞速/观察实时状态机拆到 `fieldActivityRules.ts`，随室外场景加载。
- 首次进入只准备当前地区；六区景观分别输出独立 chunk。旅行地图卡片 hover/focus 时预取目标地区，神庙入口有意图预取，不预取所有地区。
- 水域的港湾建筑、棕榈、海鸥和鱼群随 `scenery/regions/water.ts` 的独立边界加载；其它地区不加载这些几何构造。通用环境在水域跳过原野植被、山脉背景和内陆遗迹的显示，水面、角色移动和地图使用相同的地区地理数据。HUD 仅使用 `worldLayout.ts` 的轻量地区坐标 getter，不因地理差异导入 3D 工厂或寻路模块。
- 地图、图鉴、打卡、奖励、安抚等弹窗在打开时加载。神庙内部代码在准备进入时加载。
- `createModuleLoader` 缓存已加载的 JavaScript 模块，合并并发请求，失败不留永久失败缓存。`AsyncView` 忽略已取消界面的旧结果，提供重试与刷新入口。
- 每次进入场景都会创建新的 GPU 对象，退出/异常后释放 geometry、material、renderer、动画帧与事件监听器。模块缓存不保存场景实例。
- 头像进入可视区域后才加载渲染服务。队列按键去重、串行工作；每批使用一个临时 renderer，空闲后销毁。输出图片的 LRU 缓存限制为 12 条且不超过 8 MiB 的估算字符串内存；离屏或卸载取消该消费者，不影响其他等待同一头像的组件。

浏览器会缓存成功导入的 JS 模块，不能靠切换地区卸载这部分代码；需要释放的是场景 GPU 对象和有界缓存。当前人类和宠物工厂共享；宠物源码虽按物种组织，仍由统一工厂同步注册，不代表每只宠物单独下载。将来单只宠物素材显著增大时，再引入对应的异步资产边界。

探索记录每地区最多保存 144 个地图格和注册地标 ID；普通移动遥测在没有新格或地标时提前返回，不进行存档读取、JSON 序列化或写入。只有发现新增内容才更新持久状态；存储失败期间保留重试。地图迷雾使用固定数量 SVG 格子，不为每次移动追加路线节点或图片缓存。

## 度量与预算

运行 `npm run build && npm run check:bundles`。报告写入 `dist/bundle-report.json`，大小按实际构建文件分别 gzip 后累加；**不是网络耗时或帧率预测**。

| 检查项                                   |    预算 |
| ---------------------------------------- | ------: |
| HTML 静态依赖 JS，原始体积               | 320 KiB |
| HTML 静态依赖 JS，gzip                   | 100 KiB |
| 入口 + 室外控制器 + 原野及共享依赖，gzip | 310 KiB |
| 单个地区独立代码，gzip                   |  12 KiB |
| 共享 Three.js，原始体积                  | 550 KiB |
| 首屏 CSS，gzip                           |  18 KiB |

“首屏”是界面外壳，“首次可玩”还需要 3D 引擎、角色和当前世界，因此不能把外壳缩小比例说成整个游戏同等变快。第一次打开仍会请求当前世界，后续地区和室内延后加载。公共几何 kit、角色模型和引擎只加载一次。

声音功能新增了激活/偏好控制和常驻开关，界面入口 gzip 实测增加约 3 KiB，因此本次将入口预算从 95 KiB 调整为 100 KiB；声音设置面板和合成引擎仍单独按需加载，引擎 gzip 预算为 16 KiB。

新增内容导致预算失败时，先检查依赖闭包和可延迟资源；确需调整预算时在变更中记录产物差异与原因，不自动放宽阈值。地区注册新增后也要同步体积脚本列表。

## 宠物模型与栖地

`models/pets.ts` 保留统一的 `createPet` 接口。烁牙的三个成长形态由 `ember.ts` 构建；其余五种伙伴分别位于 `models/petSpecies/`，独立定义身体比例、轮廓和特征动作。`anatomy.ts` 只复用有限的几何助手与腿部骨架，`pets.ts` 负责双足/四足步态、体型缩放和飞行状态。上述物种模块均为静态导入，跟随使用工厂的场景或头像渲染服务加载；不能把源码分文件当成网络懒加载。

每次构建模型都有独立的 `modelKit` 资源所有权。同一实例内复用球体、棱面和爪形等基础几何，所有实际使用的几何与材质交给 kit 登记，初始化异常或退出时统一释放；重复 `dispose` 不重复释放。特征动作只修改既有节点变换或材质参数，不在动画循环中创建几何、材质或纹理。

`petSpecies.test.ts` 对五个独立物种限制为每只不超过 64 个 Mesh、26,000 个三角形，并验证动画前后仍使用同一批 GPU 资源。这是模型复杂度上限，不等于整帧 draw calls 或帧率保证；烁牙成长形态另外接受现有模型生命周期和步态测试。支撑脚使用按实际移动距离积累的相位；飞行坐骑更新组内鞍座锚点，再由场景变换到世界坐标，以兼容模型成长及骑乘缩放。

`scenery/petSanctuary.ts` 随室外控制器加载，按当前地区仅构建一种遭遇栖地。静态细节由 scenery kit 按材质合批，动画节点数量固定；测试约束最终栖地不超过 18 个 Mesh，并验证跨次进入、动画更新和重复销毁的资源释放。栖地没有新增网络素材，也没有放宽入口、首玩或地区包预算。

## 添加真实素材时

把资源定义放在所属地区/伙伴模块，通过 `new URL('./asset.glb', import.meta.url).href` 或构建支持的资源导入取得带 hash 的 URL。避免根入口遍历所有素材，或把大图片/模型转为源码内联 base64；只在进入地区或对象接近可见范围时请求。

开始引入 GLB、贴图或音频时，同步落地以下具体契约：

1. 素材描述包含稳定 ID、版本/URL、估算大小、适用地区和低质量替代项。loader 与 React 视图解耦，请求去重并可取消或忽略过期结果。
2. 明确缓存所有权：共享纹理/几何使用引用计数；实例销毁只释放自己的资源，最后一个使用者离开才释放共享 GPU 资源。CPU 下载缓存与 GPU 实例缓存分开设上限。
3. 贴图按目标屏幕限制尺寸并提供压缩格式，模型按视距使用 LOD/实例化；压缩解码器也通过独立入口按需加载。对新增资产实测下载体积、初始化耗时、draw calls 和移动端显存。
4. 加载进度、失败重试、低质量回退与离开场景后的清理必须一并实现。为重复进出场景加入资源数量不持续增长的回归验证。

现阶段没有虚构素材清单或预先引入多套解码器；首次引入对应资源类型时再实现并测试这些契约。

## 静态部署

`dist/index.html` 应使用可重新验证的缓存策略，例如 `Cache-Control: no-cache`；带内容 hash 的 `assets/*` 可使用 `public, max-age=31536000, immutable`。具体 HTTP header 由部署平台配置，Vite 构建不会自动替线上服务器设置。

发布时保留上一版本 hash 资源一段时间，避免已打开页面随后访问新场景时旧 chunk 404；HTML 与新资源应原子切换。现有加载失败界面可刷新取得新入口，存档不会因重载代码而清空。未来离线支持需要单独设计 Service Worker 版本和迁移策略，当前未启用离线预缓存。

## 音频生命周期

音频控制器在实际用户输入中创建/恢复 AudioContext，再异步载入合成引擎，以遵守[浏览器交互激活要求](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)。背景音乐与音效使用独立音量；页面隐藏或静音时停止调度，离开应用时断开节点并关闭 context。解锁失败可以重试，不回放用户离开场景前积压的音效。

当前音频没有网络素材缓存；若后续加入录制配乐，再按地区加入下载/解码队列、缓存预算与授权记录，不能通过根入口一次导入所有曲目。

## 原野互动扩展

村落差异化细节仍按材质合批。原野收紧为7只动物，分布在湖岸、林隙、营地与花海；动物和三处引路鸟低枝合计155个实例，使用三个实例批次。观察时显示一个共享金环。所有受惊移动仍受各自栖地边界限制；保留五种图鉴与旧存档。原野通用层的额外鸟群、蝶群已移除，微尘减少到16个。竞速仍只有固定数量的圆环、旗帜和标记。

原野植被分别提供近处与远处的树冠、枝干、灌木和草簇。草在28米内使用完整草簇、28–65米使用较低面数，65米外不绘制细草；远树与灌木继续保留整体形状。玩家累计移动3米才重排既有实例缓冲，静止时不重复上传；场景退出由context统一释放几何、材质与实例。灌木几何经归一后实高1.1–2.3米，避开主路、出生点、交互点与视点走廊。81个位置采样的植被预算接受60万三角上限检查；这不是手机实测帧率。

天空云层、路面颗粒、石材和木纹通过有限的程序化材质细节实现，无网络贴图或新增依赖。原野和水域建筑使用同一材质模块；侵蚀岩体在自然山石与瀑布间共用几何工厂。共享代码同时接受首玩依赖总量检查，地区独立包和首玩预算均未提高。当前首玩JS gzip为304,836字节，入口102,043字节；最终发布仍以该次构建清单为准。

## 水域生态与港湾

水域继续使用程序化几何，没有新增外部模型、贴图或音频资源。棕榈、岸边植被、贝壳和建筑静态细节由 scenery kit 按材质合批；海鸥使用有界数量的动画对象，三群鱼的身体和尾鳍使用两个实例批次。动画和静态对象共用 kit 的资源所有权，退出地区或初始化失败时统一释放，不在模块缓存中保存可复用的 GPU 实例。

地形与海湾参数属于轻量游戏地理数据，渲染和碰撞读取同一份定义；动物造型及动画留在地区分包。这样增加港湾细节不会把水域模型带入原野首玩依赖。产物大小仍以构建报告为准，并继续接受现有单地区预算检查。
